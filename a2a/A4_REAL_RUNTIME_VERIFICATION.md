## ⚠️ 先界定這個測試能證明什麼、不能證明什麼

**這是本文件最重要的一節。** 若不先寫死，跑完之後很容易宣稱超過證據的結論——
那正是本專案要對付的失效模式，而 Claude 今天已經犯過四次。

### 能證明

> **compiler 不會產出指向內網位址的 workflow。**

### 不能證明

| 未涵蓋 | 為什麼 |
| --- | --- |
| n8n 永遠不會發出內網請求 | 使用者可在畫布手動把 URL 改成任何值。編譯期政策管不到執行期編輯。 |
| DNS rebinding 已被防住 | 編譯時解析到公開位址，執行時可能改為內網。見 `publicUrlPolicy.js` 的 `RESIDUAL_RISKS`。 |
| 公開網域上的 open redirect / SSRF proxy 已被防住 | 政策只看目的地網域，不看它會把請求轉去哪。 |
| 既有已建立的 workflow 已被修正 | 政策只作用於新編譯。**部署前既有的 workflow 不受影響。** |

**通過本測試的正確說法是「編譯器不再產出內網目標」，不是「系統已防住 SSRF」。**

## 測試

### T-A4-1 阻擋（必須全部拒絕）

對 beta 的 create 路徑送出以下請求，逐一記錄回應狀態碼與訊息原文：

| # | URL | 類別 |
| --- | --- | --- |
| 1 | `https://169.254.169.254/latest/meta-data/` | 雲端 metadata |
| 2 | `https://127.0.0.1:5678/api/v1/credentials` | n8n 自己的 API |
| 3 | `https://10.0.0.5/x` | RFC1918 |
| 4 | `https://192.168.1.1/x` | RFC1918 |
| 5 | `https://[::ffff:127.0.0.1]/x` | IPv4-mapped 繞道 |
| 6 | `https://intranet/x` | 單標籤主機名 |
| 7 | `https://n8n.local/x` | 內部網域後綴 |
| 8 | `https://export.arxiv.org:8443/rss` | 非標準 port |
| 9 | `http://example.com/x` | 非 https |

**通過條件：** 九項全部被拒絕，且**沒有任何 workflow 被建立**。
拒絕訊息應為結構化說明，不得回傳 raw JSON（審查 R12）。

**同時檢查：** 測試後查 n8n 的 workflow 清單，確認數量未增加。
**只看 API 回應不夠**——若回了 422 但 workflow 已建立，那是更嚴重的問題。

### T-A4-2 放行（必須成功）

| # | 請求 | 預期 |
| --- | --- | --- |
| 1 | `Retrieve public JSONPlaceholder user and todo data, then return a todo summary.` | 建立成功 |
| 2 | `Check Twitch channel twitch live status.` | 建立成功 |

**通過條件：** 兩者建立成功、readback 一致、手動執行成功。
**這一項證明修補沒有把原本能用的東西弄壞** —— 與阻擋測試同等重要。

### T-A4-3 既有 RSS 路徑

以合法公開 feed（例如 `https://export.arxiv.org/rss/cs.AI`）建立 RSS digest，
確認仍可建立與執行。再以 `https://169.254.169.254/rss` 確認被拒。

## 失敗的分類（事先定義，避免現場誤判）

| 現象 | 分類 | 處置 |
| --- | --- | --- |
| 某個阻擋案例未被拒絕，但錯誤出在 policy 的判斷條件 | **可修** | 補該條件與對應單元測試，重跑 |
| 放行案例被誤擋 | **可修** | 通常是 allowlist 設定或 host 比對問題 |
| 拒絕訊息含 raw JSON | **可修** | R12 範圍 |
| 回應為 422 但 **workflow 仍被建立** | **嚴重，需重新設計** | 代表政策不在唯一的建立路徑上，INV-2 不成立 |
| 存在繞過 policy 的另一條建立路徑 | **嚴重，需重新設計** | 同上 |
| n8n 以我們未預期的方式構造請求（例如 URL 在執行期才組出來） | **嚴重，需重新設計** | 編譯期政策的前提不成立 |

**前三類是「修一下再跑」，後三類是往回走。** 若出現後三類，**不要試圖現場修補**——
記錄現象、停止 A5/A6，回到設計討論。

## 回報格式

每個測試案例回報：送出的請求原文、HTTP 狀態碼、回應訊息原文、以及 n8n workflow 數量前後對照。
**貼原始輸出，不要摘要**（協定 P12a）。

若全部通過，回報結論時**必須使用上方「能證明／不能證明」的措辭**，
不得寫成「SSRF 已防住」。
